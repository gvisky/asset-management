## Modules
1. **Asset Inventory** — 3 countries (Vietnam/Thailand/Malaysia); search + filters (country, location, brand, department, status, **Asset Type** — landing view defaults to Laptop); clickable dashboard cards; **Needs Attention** (missing info, Active without AD Name, duplicate serials; some asset types exempt); **Missing AD & Asset** inline filter; AD Name column; department / cost center / ECC CC linked dropdowns; **Print Delivery Form** (company .xlsx) from Edit / View Detail; **Recycle Bin** (soft delete + restore, admin; permanent delete for IT admin); audit log. Asset status = **Active / Broken / Stock**.
   - **Locks:** Serial / Brand-Model / Asset Code are IT-only to edit, IT admin unlocks. **History Usage** = holder lock (User Name / AD Name changes) feeding the SAP update list. **Locked models** (Dashboard Top Models) block delete and freeze Asset Type / Brand-Model / Serial for everyone until unlocked.
2. **Auth & Access Control** — login, roles, region scoping, regional admins (admin + a country can restore their region only), global-admin-only user management (with team selector). HR-only users (`asset_access = 0`) are redirected away from all asset pages.
3. **User Inventory (HR/IT offboarding)** — VN/TH/MY personnel; HR sets **User Type** (Hayat / No Hayat Member) + **Leaving Date**; **Status is manual-only** (to be delete / pending delete — shown as "Confirmed Delete" / deleted); editing is IT-admin only. Department + Cost Center (linked to assets via AD Name = email local-part, with linked-assets modal). Add User, **IT CSV import / sync** of the raw Azure export (auto-filters to the 3 countries, upserts by email, never overwrites edited rows). Monthly re-import reminder for IT.
   - **AD user list upload** (IT admin, `⬆ Upload AD list`): the Active Directory export (.xlsx/.csv: SAM Account Name, Display Name, Manager, OU Name, Last Logon Time). OU → country (VN / TH / MLY / CN); `…/Resources` OUs are shared mailboxes / groups — added too, flagged `ad_resource` (badge **Resource**, filter "AD: resource accounts"). Matching: remembered AD account → email before @ → same name in the same country (names with different "(…)" tags never match). Preview first: new people (shared/function accounts unticked), doubles to merge (the double's HR fields fill blanks, then it's removed), country differences, people not in AD. Stores `ad_sam`, `ad_manager`, `ad_ou`, `ad_last_logon`, `ad_never_logon`, `ad_seen_at`; filters "Not in latest AD list", "no logon 90+ days", "never logged on". Safe to repeat. Logic: `lib/ad-import.js`.
4. **Server Inventory** — 150 servers, separate from the main asset list; Producer + Category columns/filters.
5. **Warranty & Maintenance** — page also lists all **Broken & Stock** assets (summary chart). Broken laptops get a **parts check** (`assets.parts` JSON: Total broken, or Screen / Mainboard / RAM / Keyboard / Battery / SSD-Storage / Charger = usable / broken / used as spare; written to History Usage) and a **Spare parts** stock: every broken laptop counts as 1 of each part unless marked broken / used or Total broken; Screen / Keyboard / Mainboard / Battery counted **per model** (fit the same model only), RAM / SSD / Charger counted together (fit any laptop); Use = taken for a repair. API: `/api/maintenance/devices`, `/devices/:id/parts`, `/spare-parts`.
   Previously: — purchase date, warranty expiry, vendor, cost, PO; maintenance logs linked to assets & servers.
6. **Software & License Management** — department + current seat users.
7. **Reports & Export Center** — Full Asset Inventory report + re-upload sync (import is IT-admin only), Locked Items report, **Budget export** (round-trippable). Downloads are no-store / cache-busted. **New (Nov 2026):** Devices (Intune / Entra + differences), User activity (AD / Intune / Entra last seen + needs check; HR & IT), Broken & Stock + spare parts (parts logic shared in `lib/parts.js`), System Health (IT team). Page grouped by area. **Nov 13:** + KPIs, Depreciation & book value, Stocktakes, Handover & return, Leavers checklist (HR & IT), M365 licence reclaim, QR labels & scans log (role admin), My devices confirmations (HR & IT) — `lib/report-extra.js` (KPI numbers from `routes/kpi.js computeKpi`, reclaim from `routes/m365.js computeReclaim`). **Excel = Dashboard sheet** (KPIs, summary tables, native Excel charts — `lib/report-excel.js`: ExcelJS + DrawingML chart parts added with JSZip) **+ raw data sheets; PDF = dashboard** (`lib/report-pdf.js`, pdfkit + bundled DejaVu fonts in `assets/fonts`). Asset / User sync uploads read the `Assets` / `Users` sheet (Dashboard ignored). **HTML** (`lib/report-html.js`): self-contained interactive page — dashboards for All + each country, sortable matrix tables, % toggle, mix-bar tooltips, data tabs with search / country filter / paging / CSV.

9. **Notifications / Alerts** — alert boxes on Dashboard / Asset Inventory / User Inventory + Needs Attention alerts page; audience-aware (IT/HR/all) + region-scoped; events for HR/IT changes, asset delete/restore, imports.
10. **Dashboard** — **New app function update** box (latest deployments, from `public/data/app-updates.json`), asset stats, per-country cards, Top Models by Asset Type (with delete-lock), User Inventory summary cards, consolidated alerts.
11. **Mobile / phone UI** — off-canvas hamburger sidebar, card-view tables, iPhone safe-area support (desktop layout unchanged).
12. **Devices (Intune + Entra)** — IT admin imports 3 Microsoft exports (Azure users, Intune devices, Entra devices); they are linked by email (person ⇄ device), Intune Device ID / device name (Intune ⇄ Entra) and Computer No / Serial (device ⇄ asset). Devices page with compliance, last sign-in, owner and asset links; "Fill assets from Intune" fills only empty asset fields. Devices can be **added** to Asset Inventory (bulk or one by one; Brand / Model learned from existing assets with the same model; personal/BYOD devices unticked by default) and device users missing from User Inventory can be added (IT admin). **➕ Add all to Asset Inventory** adds every device with a known country in one go (in steps of 500). The Devices page shows by default only devices still **to add** (not in Asset Inventory, or user not in User Inventory). Device ⇄ asset links and first-seen dates are remembered across imports (`device_links`, `device_seen`), so later imports only surface **new** devices; the first big import is the baseline (no "New" badges for it). The exports never contain Asset code, Asset S/4, Location (Office/Factory), Department / Cost center or Purchase date — those stay to fill and show in Needs Attention. The Azure users file updates User Inventory for **all countries** (people only — guests and service accounts skipped).
   - **Imports are off** unless Render has `IMPORTS_ENABLED=1` (the first all-countries import added too many assets). **↩ Undo Microsoft import** (IT admin, Devices page) removes what the imports added since 30 Oct 2026 03:20 UTC — assets created from devices and people added by the import that nobody edited by hand, Intune fills, the Devices list and its links — with a preview first. Hand-edited assets / people are kept and listed.
12b. **Device Check (Intune + Entra vs Asset Inventory)** — see `docs/DEVICE-CHECK.md`. IT admin uploads the Intune + Entra device exports on the Devices page (**⬆ Upload Intune + Entra**, preview → apply). Only devices of people in the **AD list** are kept; only the Devices list is replaced — **Asset / User Inventory are never changed by the upload**. Computers are matched to assets (Computer No, else serial) and differences are flagged (not in Asset Inventory, serial, PC No, user, brand, PC No & serial on two assets). Per difference: **Use Intune value** (one field, history + audit, same locks, refuses duplicates) or **Mark as checked** (remembered in `device_ack`). Devices page default view **Needs check**; compliance, ownership, managed by, days since check-in / sign-in. **Asset Inventory → View: by user** (default): one block per holder with their assets, each asset's Intune status, and their Intune devices not in Asset Inventory (highlighted) + phones / tablets.
13. **System Health** _(team IT)_ — live status of routers / switches / servers / internal web apps. The website can't reach the office networks, so a **collector** (`collector/`, Node + SNMP) on an always-on office PC checks them every minute (SNMP / ping / HTTP / TCP port) and pushes the results to `/api/health/ingest` with its own key (IT admin creates keys on the page; shown once, stored hashed). Only the latest status + status changes are stored. IT gets 🔔 alerts when a system goes down / amber / back up, or a collector stops reporting (office internet down?). First target: DrayTek Vigor2133 at 192.168.3.1 (SNMP read-only). Setup: `collector/README.md`.
15. **KPIs** (`kpi.html`, `routes/kpi.js`) — per country: utilisation **per asset type × country** (Active ÷ assets of that type, target 85–90 %; types never combined), ghost assets (missing in the latest closed stocktake per country / site), data quality **per asset type × country** (same rule as Needs Attention, with the reasons), repair time (Maintenance log, 12 months), leaver recovery (≤ 7 days), depreciation (cost, book value, fully depreciated still Active). Daily snapshot per month in `kpi_snapshots` → trend.
16. **Depreciation** (`lib/finance.js`) — straight-line from Purchase Date, **5 years** (Finance; VN Circular 45/2013 Annex 1 allows 3–8 years for IT / electronic management equipment); years per country editable by a global IT admin (KPIs → ⚙). Book value in the asset detail view. Cost text parsed ("18,992,364 VND").
17. **Leavers** (`leavers.html`, `routes/leavers.js`, HR + IT) — people with a Leaving Date (−120 / +60 days) or marked for delete; checklist in `leaver_items`: `asset:<id>` (done by an e-signed return or when the asset gets another holder), `device:<id>` (Intune, IT ticks), `m365` (licence; auto when the report shows none), `ad` (auto when not in the latest AD list). Recovery = assets back ≤ 7 days after the leaving date.
18. **Stocktake + QR labels** — filters per campaign: status / asset type / department (`stocktakes.status_filter, department, asset_type`; scanned here but outside the filter = `outside`). Every label print is logged with its purpose (`qr_prints`), every scan (`qr_scans`: who, when, source, result, IP); admins (role admin) see the counts on labels and the history on the asset; admins are asked for a photo after a scan (`asset_photos`, JPEG ≤ 1280 px). — (`stocktake.html`, `labels.html`, `scan.html`, `routes/stocktake.js`) — campaigns per country or VN site; phone camera scan (BarcodeDetector, else bundled jsQR for iPhone) or typed code / serial / PC name; found / found elsewhere (Move here → history) / missing / unknown; closing stores the result (ghost KPI). Labels A4 3 × 7 (63.5 × 38.1 mm) or label printer; the QR holds only `/scan.html?a=<id>`. Stocktake lists: grouped by model (closed by default), extra info per asset (dates, warranty, remark, parts condition — `/api/stocktake/:id` sends `condition`, not the parts JSON), ✏️ quick edit (`public/js/quick-edit.js`: GET asset → PUT the full record, parts check on Broken, IT-admin unlock); the labels list (`public/js/labels.js`, `window.LabelsPanel`) opens as an in-page panel (`#lb-panel`) on Stocktake and is still the QR labels page.
19. **My devices** (`routes/confirm.js`, `public/my-devices.html`, User Inventory 📨) — IT admin makes a personal link (random secret, only its SHA-256 stored, 14 days, new link revokes the old) + a ready email with a button; the public page shows the person's assets (AD Name = email local part) only after they type the email on record (5 wrong → locked; 40 calls / 10 min per IP); answers per asset (have / not with me + note), signed with the checked work email; phones / tablets from Intune (`devices`, kept by `device_key`): Turkish staff (recognised by name in `routes/confirm.js`, override `personnel.mobile_policy`) confirm them, others see them as "also signed in on" → `asset_confirmations` (time, IP, browser), audit log, IT alert for "not with me" / extra device. `confirm_links` keeps opened / verified / confirmed times.
19. **E-signed handover / return** (`routes/custody.js`, `public/js/custody.js`, `lib/custody-pdf.js`) — signature pad → PDF (DejaVu, VN/EN) stored in `asset_docs` with SHA-256; handover sets holder (User Name, AD Name = email before @), Date Assigned, Active; return clears holder → Stock / Broken (+ parts check for laptops). Same holder-lock rule as Asset Inventory edits.
20. **Microsoft 365 licence reclaim** (Licenses page, `routes/m365.js`) — global IT admin uploads the admin centre **Active users** export (columns found by pattern; refuses reports with concealed names); reclaim list = leavers still licensed + no activity in any service for 30 / 60 / 90 / 180 days + never active; per country; CSV.
14. **Backup / restore** — `npm run backup` (all tables → timestamped JSON), `npm run restore` (see `DISASTER-RECOVERY.md`).

## Safety rules in the code (bug review 10 Nov 2026)
- All data shown in pages goes through `htmlEsc()` (app.js); names passed to buttons use `jsArg()` — never raw `${value}` in innerHTML / onclick.
- Endpoints that change data of a country check the user's country scope (`lib/scope.js`); uploads that replace data of every country (AD list, Intune + Entra, undo) are global IT admin only.
- Request bodies are limited to 1 MB unless the user is logged in (uploads up to 75 MB).

## Working rule (avoid conflicts)
The project is **one repo + one live site + one database**. Every push to `main` goes live immediately and works on real data.

- Make changes on a **feature branch** (e.g. `claude/...`), review, then merge to `main` to deploy.
- Work in **one place at a time**. If a local copy is still used, `git pull origin main` before touching it.
- After a deploy, verify on https://asset.hayat.io.vn (the `test` account is available for this).
- With every user-visible change, add an entry to `public/data/app-updates.json` (date, title, short points) — it feeds the Dashboard's **🚀 New app function update** box.
